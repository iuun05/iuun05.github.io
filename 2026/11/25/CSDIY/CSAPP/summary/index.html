信息的表示

这本书称为被奉为计算机的圣经也不是没有原因的，从基本的 0-1 编码和相关计算开始讲起，然后讲述了我们怎么通过 0 和 1 这两个值来表示不同类型的数据，比如说整数，浮点数，字符串，文本。信息的本质就是位 + 上下文。

代码如何变成可执行的机器指令

当我们直到程序组成的元素是什么之后，我们就会好奇，一个代码文件，是怎么跑起来的。书中明确的给出答案，代码变成可执行文件需要执行四个阶段:

  • 预处理：处理宏定义、头文件包含、条件编译等，生成预处理后的源代码。
  • 编译：将预处理后的源代码转换为汇编代码。
  • 汇编：将汇编代码翻译成机器码，生成可重定位目标文件（.o）
  • 链接（Linking）：现代程序往往由多个源文件组成，链接器负责符号解析（把函数和变量的引用与定义对应起来）和重定位（合并代码段与数据段，分配最终的内存地址），最终打包成 ELF 格式的可执行文件，或者通过动态链接库（.so）在加载和运行时动态绑定。

当可执行文件被加载并建立运行环境后，CPU 就可以从内存中读取机器指令，通过译码和执行过程驱动处理器内部的运算单元、寄存器和控制逻辑，从而完成程序所描述的计算任务。

目标文件

目标文件（Object File）是编译器和汇编器处理源代码后，生成的具有特定格式的二进制文件（Linux 下是 ELF 格式，Windows 下是 PE 格式，macOS 下是 Mach-O 格式）。目标文件主要是三种类型，分别是：

  • 可重定位目标文件：包含二进制代码和数据，其形式可以在编译时与其他可重定位目标文件合并起来，创建一个可执行目标文件。
  • 可执行目标文件：包含二进制代码和数据，其形式可以被直接复制到内存并执行。
  • 共享目标文件：一种特殊类型的可重定位目标文件，可以在加载或者运行时被动态地加载进内存并链接。

组成部分 作用说明
ELF header 位于文件开头，描述生成该文件的系统字长（32/64 位）、字节序、文件类型（可重定位/可执行/共享）、机器类型（如 x86-64）以及 Section header table 的偏移与条目大小。
.text 已编译程序的机器代码。
.rodata 只读数据（Read-Only Data），例如 printf 中的格式字符串、字符串字面量、switch 语句的跳转表。
.data 已初始化的全局和静态 C 变量（局部变量保存在运行时的栈中，不出现在 .data 或 .bss 里）。
.bss 未初始化（或初始化为 0）的全局和静态 C 变量。它只是一个占位符，在磁盘文件中不占用实际空间（记忆口诀：Better Save Space），运行时才由系统分配并清零。
.symtab 符号表，记录本模块中定义和引用的所有函数与全局变量信息（不含局部变量）。
.rel.text .text 节中需要被修改的位置列表。凡是调用了外部函数或引用了全局变量的指令，在合并时都需要按此表修正地址。
.rel.data 被本模块引用或定义的所有全局变量的重定位信息（例如一个全局指针初始化为另一个全局变量或函数的地址）。
.debug / .line 调试符号表与 C 源码行号到机器指令的映射表，只有在编译时加上 -g 选项才会生成。
.strtab 字符串表，以 \0 结尾的字符串序列，存放 .symtab 和 .debug 中用到的符号名字，以及节头部表中的节名称。
Section header table 位于文件末尾，记录上述每一个节在文件中的偏移位置和大小，相当于整份文件的目录索引。

除了 .bss 用于保存未初始化的静态变量，以及初始化为 0 的全局或静态变量之外，还有一个称为 COMMON 的区域，用于保存未初始化的全局变量。（CS:APP 第 3 版写作时 GCC 默认开启 -fcommon，但从 GCC 10（2020 年）开始默认改为 -fno-common，未初始化全局变量现在也会直接放进 .bss 并作为强符号处理，跨文件同名定义会直接报重定义错误。）

出现 COMMON 的原因是：不同目标文件中可能存在强符号与弱符号解析的问题。COMMON 是一种特殊的符号类型，用于表示未初始化的全局变量，使链接器能够在多个目标文件之间合并同名变量，并按照强弱符号解析规则处理符号冲突。

链接

链接（Linking）是将各种代码和数据片段收集并组合成一个单一文件的过程，这个文件可被加载（复制）到内存中并执行。链接由链接器（Linker）完成，核心包含符号解析和重定位两个步骤。它支持分离编译，使我们能够把大型工程拆分为多个独立模块，分别修改和编译，而无需每次都重编整个项目。

按链接发生的时机，主要分为两种形式：

  1. 静态链接（输入 .o / .a）：在编译时由静态链接器完成，将程序依赖的所有代码和数据完整拷贝并打包进最终的可执行文件中。生成的文件体积较大，但运行时不依赖外部库。

  1. 动态链接（依赖共享库 .so）：编译时不在可执行文件中拷贝库代码，而是将链接推迟到加载时（由动态链接器完成）或运行时（由应用程序调用 dlopen 完成）。不仅能减小文件体积、方便独立更新库文件，还能让多个进程在内存中共享同一份 .so 代码。

硬件协同与存储器层次结构

硬件协同

我们知道代码是转化为指令的，那么指令是怎么在一台电脑上跑起来的？书上就开始一步一步的过渡到各部分硬件的组成和功能，比如说：

  • CPU（算术逻辑单元、寄存器文件、程序计数器）
  • 磁盘
  • 内存
  • I/O 设备

这些部件通过总线（Bus）连接在一起，负责在彼此之间传递地址、数据与控制信号。

以 hello 为例子，有以下的步骤：

  1. 用户输入命令

初始时，Shell 程序执行自己的指令，并等待用户输入命令。当我们在键盘上输入 ./hello 时：

  • 键盘将输入信息传递给计算机。
  • Shell 程序读取用户输入的字符。
  • Shell 将读取到的命令字符串存放在主存中。

此时，Shell 负责接收命令，并准备执行对应的程序。

  1. 计算机加载程序

当 Shell 识别到 ./hello 命令后，会启动加载程序的过程。

  • Shell 通过系统调用请求操作系统创建进程。
  • 操作系统为新进程建立运行环境。
  • 加载器（Loader）将 hello 程序的代码和数据从磁盘加载到主存。
  • 操作系统完成必要的内存映射和初始化工作，准备开始执行程序。

其中，可以利用 DMA（Direct Memory Access，直接存储器存取） 技术，使数据在磁盘控制器与主存之间传输时，不必由 CPU 逐字节搬运，从而减轻 CPU 的数据传输负担。

  1. 执行程序

当 hello 程序的代码和数据被加载到主存后，处理器开始执行程序中的机器语言指令。

CPU 通过不断执行取指、译码和执行操作来运行程序：

  • 取指（Fetch）：根据程序计数器 PC 中的地址，从主存中读取下一条机器指令。
  • 译码（Decode）：分析指令的操作类型以及需要使用的操作数。
  • 执行（Execute）：由 ALU 或其他执行单元完成相应操作，并更新寄存器或内存。

CPU 不断重复上述过程，直到程序执行结束。

  1. 输出结果

在执行 printf("hello, world\n") 时：

  • CPU 执行相关指令，将字符串数据从主存读取到寄存器。
  • 程序通过调用 I/O 相关接口，将输出请求交给操作系统。
  • 操作系统通过 I/O 子系统将数据传递给显示设备。
  • 最终，字符串 hello, world 显示在屏幕上。

性能提升

而在 CPU 内部，为了不让硬件闲置，现代处理器引入了流水线（Pipelining）机制，让多条指令的不同执行阶段重叠进行，同时通过硬件转发、暂停和分支预测来化解数据冒险与控制冒险。

当程序能运行起来之后，我们应该怎么去优化，去提升他的效率。比如说：

  • 从硬件/指令集上：

    • （配合硬件）优化指令实现逻辑
    • 使用性能更高的元器件，多核处理器
    • 使用流水线优化指令执行效率：现代处理器支持超标量、乱序执行和分支预测
    • 指令并行

  • 在软件/算法上

    • 局部性

  • 程序员角度，主要是编写出优质代码，书中主要介绍了两点：

    • 循环展开（n x 1 展开；n x n 展开）
    • 利用好局部性

操作系统抽象

如果每个程序都要直接去操作裸机硬件，我们需要防止程序相互修改彼此之后的内存信息，还需要控制什么时候应该该哪个程序运行，开发成本会高到难以想象。操作系统的出现为我们提供了非常便利的服务。

异常与进程

计算机系统通过异常机制实现对程序执行流程的控制。当发生特定事件时，CPU 会暂停当前程序的正常执行，将控制权转移给操作系统内核，由内核执行相应的异常处理程序。

常见的异常类型包括：

  • 硬件中断（Interrupt）：由外部硬件设备触发，通常是异步发生的，例如键盘输入、时钟中断和 I/O 完成。
  • 陷阱（Trap）：有意触发的异常，通常用于实现系统调用，使用户程序能够请求操作系统提供服务。
  • 故障（Fault）：由当前指令执行过程中检测到的错误引起，例如缺页故障（Page Fault）。处理完成后，可能重新执行引发故障的指令。
  • 终止（Abort）：由严重错误引起，通常无法恢复，例如硬件故障或严重的程序错误。

异常机制使操作系统能够及时响应外部事件、处理程序运行中的错误，并控制程序的执行流程。

在异常控制流的基础之上，操作系统抽象出了进程（Process）。

进程是操作系统对正在运行的程序的一种抽象，它为每个程序提供了独立的逻辑控制流，使程序看起来仿佛独占了 CPU。

操作系统通过**上下文切换（Context Switch）**实现多个进程之间的交替执行：

  • 保存当前进程的运行状态，例如寄存器、程序计数器和栈指针。
  • 恢复下一个进程之前保存的运行状态。
  • 将 CPU 控制权交给下一个进程。

通过这种方式，多个进程可以共享 CPU 资源，实现并发执行。

信号是操作系统提供的一种软件形式的异常控制流，用于向进程通知某种事件已经发生。

信号具有异步性，进程不需要主动查询，就可以在执行过程中接收到信号，并根据相应的处理方式作出响应。

信号的常见来源包括：

  • 内核向进程发送信号，例如发生除零错误、非法内存访问或定时器到期。
  • 一个进程通过 kill 等系统调用向另一个进程发送信号。
  • 用户通过终端输入特定组合键，例如 Ctrl+C 产生 SIGINT 信号。

进程收到信号后，可以执行默认处理动作、忽略信号，或者执行预先注册的信号处理函数（部分信号不能被忽略或捕获）。

信号为操作系统和进程之间提供了一种异步事件通知机制。

虚拟内存

为了让每个进程拥有独立、安全且规整的地址空间，操作系统配合硬件 MMU + TLB 和页表引入了虚拟内存。它一石三鸟地扮演了三个角色：

  • 内存保护的工具（进程间隔离与权限控制）
  • 内存管理的工具（简化链接、加载与 mmap 内存映射）
  • 主存作为磁盘缓存的工具。

而在进程内部的堆区，我们还需要通过动态内存分配器（如隐式/显式空闲链表、分离适配与边界标记合并）来高效管理 malloc 与 free。

另外还简单的提到了 GC 是怎么借助可达图实现垃圾内存收集的。保守式标记-清除（Mark & Sweep）垃圾收集器，借助可达图回收的是已分配但程序不再能访问到的垃圾块（防内存泄漏），

系统级 I/O

Unix 将许多 I/O 资源统一抽象为文件，通过**文件描述符（File Descriptor）**提供统一的访问接口。

比如，常见的文件描述符 stdin 0, stdout 1, stderr 2

普通磁盘文件、终端设备、管道以及网络套接字等，都可以通过文件描述符进行访问。程序不必直接关心底层设备的具体实现，而是通过统一的系统调用完成 I/O 操作。

常见的系统级 I/O 操作包括：

  • open：打开文件，获取文件描述符。
  • read：从文件描述符读取数据。
  • write：向文件描述符写入数据。
  • close：关闭文件描述符。

网络

我们想要与其他计算机通信，我们就需要网络了。网络本质上是一种连接不同计算机的通信系统，使不同主机能够交换数据和共享资源。

基本的网络有：

  • 主机（Host）：网络中的计算机，负责运行程序和处理数据。
  • 路由器（Router）：负责在不同网络之间转发数据包。
  • 交换机（Switch）：负责在局域网内部转发数据帧。
  • 通信链路（Link）：连接网络设备，负责传输数据。

当我们想要给另一个网络发送一个数据的时候，我们需要统一一种数据格式，让两边的计算机都能够理解这种格式，因此出现了协议，因此发送和解析数据包的时候涉及复杂的封装。当进入到网络时候，网络实际上是非常复杂的，存在各种不稳定的情况，我们又需要实现各种机制来保证数据的及时性和稳定性。

当我们想要开发的时候，unix 系统也将网络抽象为文件，可以通过文件的方式访问网络接口（套接字）。

并发编程（Concurrent Programming）

当一个程序需要同时处理多个任务时，就需要使用并发编程。

  • 并发（Concurrency） 是指多个逻辑控制流在时间上交替推进，使多个任务在一段时间内都取得进展。
  • 并行（Parallelism） 是指多个任务在同一时刻真正同时执行，通常依赖多个 CPU 核心或处理器。

常见的并发编程方式有三种：

  • 进程（Process）：通过创建多个进程实现并发。每个进程拥有独立的虚拟地址空间，进程之间通常通过 IPC（进程间通信）交换数据。
  • I/O 多路复用（I/O Multiplexing）：通过 select、poll、epoll 等机制，同时监听多个 I/O 事件，在某个文件描述符就绪时处理对应任务。通常在单个进程或线程中实现多个连接的并发处理。
  • 线程（Thread）：在同一个进程中创建多个执行流，它们共享进程的地址空间和大部分资源，但拥有各自独立的线程上下文和栈。

多个执行流可能同时访问共享资源，因此需要考虑同步与互斥问题。

  • 竞争条件（Race Condition）：多个执行流访问共享数据时，最终结果依赖于它们的执行顺序。
  • 互斥（Mutual Exclusion）：保证同一时刻只有一个执行流进入临界区，避免并发访问造成数据错误。
  • 同步（Synchronization）：协调多个执行流的执行顺序，确保它们按照预期的依赖关系推进。
  • 死锁（Deadlock）：多个执行流相互等待对方持有的资源，导致所有相关执行流无法继续执行。

我们常见的同步方法有以下几种方式

  • 信号量（Semaphore）：通过计数器和 P、V 操作控制多个执行流对共享资源的访问。
  • 互斥锁（Mutex）：保证临界区的互斥访问。
  • 条件变量（Condition Variable）：使线程能够等待某个条件成立，并在条件满足时被唤醒。
  • 读写锁（Read-Write Lock）：允许多个读者同时访问共享资源，但写操作需要独占访问。

通过有效的同步，我们就可以使得并发程序正确的稳定的运行。
